# Контракт HTTP API

Точка входа приложения — `asgi_app:app`. Swagger доступен по `/docs`,
машиночитаемый контракт — по `/openapi.json` и `/api/openapi.json`.
Второй адрес проходит обычную проверку доступа; первый используется встроенным
интерфейсом FastAPI. Оба адреса возвращают одну схему.

## Как поддерживается актуальность

`api_openapi.py` строит схему из зарегистрированных маршрутов FastAPI.
Операции совместимости из `web_ui.Handler` выполняются через защищённый
маршрут `/api/{operation:path}` и не видны генератору FastAPI. Для них
добавляется только явный список `LEGACY_OPERATIONS` из `openapi.json`.
Описание нативного маршрута всегда имеет приоритет перед старым снимком.

В `openapi.json` остаётся совместимый справочник старых операций, а не копия
всего текущего API. При изменении нативного запроса нужно обновлять его
Pydantic-модель. При изменении результата — документированный ответ в
`api_openapi.py`. При добавлении операции в диспетчер совместимости нужны
описание в снимке и запись в `LEGACY_OPERATIONS`. После изменения регистрации
маршрутов кеш `app.openapi_schema` должен быть сброшен.

Генерация схемы не изменяет HTTP-валидацию, разрешения, фильтрацию ответа или
результат поиска. В частности, схема не должна придумывать числовой `score`
каноническому разделу, для которого ранжировщик его не возвращал.

При сохранении пользовательского сообщения через
`POST /api/chats/{chat_id}/messages` поле `status` лучше опустить:
используется значение `complete`. Статус задания `completed` не является
статусом сообщения, учитываемого в истории разговора.

## Авторизация и Swagger

В режиме локальных пользователей сначала вызывается `/api/auth/login`.
Браузер сохраняет HttpOnly-cookie `rag_session`. Для изменяющих запросов с
такой cookie требуется заголовок `X-CSRF-Token`; его значение возвращает
`/api/auth/session`. Cookie не следует копировать в документацию или исходники.
В Swagger можно выполнить вход и затем передавать CSRF-заголовок в операции.

Альтернативный настроенный провайдер идентификации может принимать Bearer.
Две схемы в OpenAPI описывают варианты конфигурации; это не означает, что
сервер принимает оба варианта одновременно. Безопасный режим не включается
и не выключается вызовом `Authorize` в Swagger.

## Ответы и фоновые операции

| Операция | Успех | Дальнейшие действия |
| --- | --- | --- |
| `POST /api/ask` | `200` — готовый ответ; `202` — генерация продолжается | При `202` использовать `job_id` либо перечитать сообщения чата |
| `POST /api/ask/stream` | `200 text/event-stream` | Обрабатывать события `started`, `heartbeat`, `delta`, `completed`, `error` |
| `POST /api/upload` | `202` — файлы сохранены и поставлены в очередь | Проверять задания и реестр документов до состояния готовности |
| `POST /api/jobs/ingestion` | `202` — принято фоновое задание | Использовать `GET /api/jobs/{job_id}` |
| `DELETE /api/documents/{document_id}` | `202` — документ скрыт, очистка поставлена в очередь | Не считать ответ подтверждением уже законченной очистки индекса |
| `GET /api/documents/{document_id}/content` | `200` — оригинальный файл | MIME-тип и имя берутся из реестра; это не JSON |

Событие SSE `error`, отправленное после начала потока, сохраняет HTTP-статус
`200`. Поэтому проверка одного кода ответа не подтверждает успешную генерацию.
В устойчивом режиме задание и сообщения сохраняются после отключения клиента.
Обычный поток без устойчивой очереди не является возобновляемым потоком токенов.

Ошибки нативных обработчиков обычно имеют вид `{"detail": ...}`; операции
совместимости могут вернуть `{"error": ...}`. Ошибки валидации FastAPI —
`422` с массивом диагностик в `detail`. Необработанное исключение сервера
может дать текстовый `500`; клиент не должен предполагать JSON при любом статусе.

## Проверка перед передачей разработчикам

Из корня репозитория:

```powershell
.\.venv312\Scripts\python.exe -m pytest -q test_api_openapi.py test_asgi_foundation.py
```

Контрактные тесты проверяют наличие зарегистрированных маршрутов, доступность
операций проектов и чатов через фасад, уникальность `operationId`, разрешение
внутренних ссылок схемы, условную CSRF-авторизацию и реальные ответы TestClient.
Для генерации, SSE и загрузки используются изолированные заглушки: эти тесты
не запускают модель, PostgreSQL, Redis и не изменяют рабочую библиотеку.
Они подтверждают контракт локального кода; публикация той же версии Swagger
на развёрнутой ВМ требует проверки после выкладки.
