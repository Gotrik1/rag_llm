# Проверка качества ответов RAG

Число «9 из 10» считается выполненным только после прогона версионированного
набора вопросов на фактических документах, модели и конфигурации retrieval.
Обычные unit-тесты не доказывают смысловое качество ответа.

## Формат набора

Каждая непустая строка JSONL описывает один вопрос. Обязательны `id`, `question`
и либо `expected_terms`, либо `expect_refusal=true`. Значения `expected_terms`
сопоставляются без учёта регистра; для слов с изменяемым окончанием указывайте
устойчивую основу (`"теплоёмк"`). Дополнительно задаются:

- `expected_sources` — части имён правильных документов;
- `expected_formula_terms` — обозначения, которые должны присутствовать в
  формулах или ответе;
- `forbidden_terms` — известные ложные утверждения;
- `max_latency_s` — допустимое время ответа.

Оценка состоит из фактов (4 балла), правильных источников (2), рабочих ссылок
(1), формул (1), корректного ответа/отказа (1) и задержки (1). Любой запрещённый
термин снимает 2 балла. Gate требует не менее 9 баллов у каждого вопроса, а не
только хорошего среднего значения.

## Запуск

Создайте отдельный проект и чат, загрузите в него ровно оцениваемую версию
корпуса и дождитесь статуса `ready`. Токен передаётся только через окружение:

```console
export RAG_EVAL_BASE_URL=https://rag.example.internal:8443
export RAG_EVAL_CHAT_ID=<uuid тестового чата>
export RAG_EVAL_TOKEN=<короткоживущий OIDC access token>
python quality_eval.py evals/production.jsonl --minimum 9 --output quality-report.json
```

Не коммитьте `production.jsonl`, если вопросы раскрывают закрытые сведения, и
никогда не сохраняйте токен в командной строке, отчёте или Git. Для релиза
архивируйте SHA приложения, модель, параметры retrieval, хеши документов,
JSON-отчёт и время прогона. После изменения модели, промта, chunking, reranker,
форматного парсера или корпуса gate запускается заново.
