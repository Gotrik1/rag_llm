# RAG Assistant подробная инструкция пользователя

## 1. Что делает система

RAG Assistant отвечает по загруженным документам и показывает, на какие
фрагменты опирался ответ. Он не «запоминает весь файл в системном промте»:
документ заранее разбивается на смысловые разделы и чанки, после чего для
каждого вопроса выбираются только наиболее подходящие фрагменты.

Система подходит для инструкций, регламентов, договоров, технических описаний,
отчётов, таблиц в тексте и документов с формулами. Поддерживаются `.docx`,
`.pdf`, `.md` и `.txt` до 50 МиБ на файл, не более 20 файлов за одну загрузку.

Важно: RAG снижает риск выдуманного ответа, но не превращает модель в источник
юридически или технически значимой истины. Для критического решения откройте
источник, проверьте раздел и действующую редакцию документа.

## 2. Основные понятия

| Понятие | Что это значит |
| --- | --- |
| Общие документы | Общий проверенный корпус, доступный всем зарегистрированным пользователям для поиска и чтения источников |
| Проект | Приватная рабочая область конкретного пользователя: память, документы и несколько связанных чатов |
| Память проекта | Короткие устойчивые правила и контекст, которые нужны во всех чатах проекта |
| Область знаний | Настройка проекта: искать только в его документах либо одновременно в документах проекта и общем корпусе |
| Чат проекта | Отдельная ветка разговора; видит память и разрешённую область документов своего проекта |
| Свободный чат | Чат вне проекта; видит общие и собственные прикреплённые документы, а история изолирована от остальных |
| Память документов | Реестр загруженных файлов со статусом и числом проиндексированных чанков |
| Источник | Открываемый исходный документ и понятный ориентир: страница, раздел, глава, пункт или приложение |
| Flow | Способ поиска/генерации: Python, Rust или гибридный |

## 3. Первый вход

1. Откройте выданный администратором HTTPS-адрес. Для текущей VM адрес
   приёмочной среды: `https://5.35.120.112:8443/`.
2. При первом входе откройте вкладку `Регистрация`, укажите отображаемое имя,
   рабочую электронную почту и пароль. Пароль должен содержать не менее 12
   символов и не должен совпадать с адресом или его частью до символа `@`.
3. После регистрации откроется рабочая область. При следующих посещениях
   используйте вкладку `Вход`. Браузер не должен показывать системное окно
   Basic Auth и не должен повторно спрашивать пароль при каждом запросе.
4. Дождитесь появления левой панели проектов/чатов. Если интерфейс открылся, но
   проекты не загрузились, обновите страницу один раз. Повторяющаяся ошибка —
   повод передать администратору время ошибки и `X-Request-ID`, если он показан.
5. Выберите существующий проект или создайте новый.

Сессия хранится в защищённой cookie и переживает обновление страницы и закрытие
вкладки. Пароль в браузерном хранилище приложения не сохраняется. Если срок
сессии истёк, учётная запись отключена или выполнен выход, система вернёт на
страницу входа. Несколько неверных попыток временно блокируют новый вход, но не
раскрывают, зарегистрирован ли конкретный адрес.

Не используйте пароль от SSH, sudo, почты или другого корпоративного сервиса.
Завершая работу на чужом компьютере, нажмите `Выйти`, а не просто закройте
вкладку.

## 4. Как организовать работу

Создавайте отдельный проект для набора документов, которые допустимо смешивать
в одном ответе: например, «Эксплуатация турбины», «Договоры 2026», «Проект А».
Не складывайте в один проект документы разных заказчиков или редакций, если их
совместное использование может привести к неправильному выводу.

Каждый проект и его чаты принадлежат создавшему их пользователю и не видны
другим обычным пользователям. В технической панели выберите область знаний:

- `Только документы проекта` — retrieval полностью исключает общий корпус;
- `Документы проекта и общие` — поиск идёт одновременно по приватным документам
  текущего проекта и по общим документам.

Настройка применяется к следующим вопросам во всех чатах проекта и входит в
ключ кэша. Переключение режима не копирует и не перемещает файлы. Если проект
должен быть максимально изолирован от общих регламентов, используйте первый
режим. Если общие правила дополняют материалы проекта, используйте второй.

Внутри проекта создавайте отдельные чаты по задачам:

- разбор требований;
- поиск формул;
- подготовка пошаговой инструкции;
- сравнение редакций;
- проверка конкретной гипотезы.

Чтобы длинная история не занимала всю навигацию, проект показывает первые
четыре чата. Нажмите `Ещё N`, чтобы раскрыть остальные, и `Свернуть`, чтобы
вернуться к компактному списку. Активный чат всегда остаётся видимым и выделен
цветом. Чаты не удаляются и не объединяются при сворачивании списка.

Несколько чатов можно использовать одновременно. Если ответ строится в одном
чате, переключитесь в другой и задайте следующий вопрос. Поздний результат
останется привязан к исходному чату и не попадёт в открытую ветку.

## 5. Память проекта

Память проекта предназначена не для копирования документов, а для кратких
правил работы. Хорошее содержимое:

```text
Отвечай для редакции регламента от 01.08.2026.
Под «объектом» в этом проекте понимается энергоблок № 3.
Если источники противоречат друг другу, перечисли противоречия и не выбирай молча.
Единицы в итогах: МВт и Гкал/ч.
```

Не помещайте туда:

- полный текст договора или инструкции;
- пароли, токены, персональные данные без необходимости;
- временный вопрос, относящийся только к одному сообщению;
- указание игнорировать источники или правила безопасности.

Изменение памяти влияет на следующие ответы и входит в область ключа кэша.

## 6. Загрузка документов

1. Откройте нужный проект или свободный чат.
2. Нажмите кнопку `+` слева от поля `Введите вопрос`. Откроется панель
   `Добавить в контекст`.
3. Выберите область использования:

   - `Только в этом чате` — файл будет доступен только в открытой ветке;
   - `Во всём проекте` — файл смогут использовать все чаты текущего проекта.

   Файл в обоих случаях остаётся приватным для владельца проекта. В свободном
   чате доступен только вариант `Только в этом чате`.
4. Нажмите карточку `Документ` для `.docx`, `.pdf`, `.md` или `.txt` либо
   карточку `Изображение` для `.png`, `.jpg`, `.jpeg`, `.webp`, `.tif`,
   `.tiff` или `.bmp`. Можно выбрать несколько файлов.
5. Проверьте список выбранных файлов и при необходимости уберите лишний файл
   кнопкой рядом с его именем. Кнопка отправки заранее показывает назначение:
   `Загрузить в чат` или `Загрузить в проект`.
6. Нажмите загрузку. API быстро примет файлы и поставит их в очередь. Закрывать
   страницу не требуется: состояние хранится на сервере и восстановится после
   обновления браузера.
7. Следите за разделами в левой панели:

   - `Общие документы` — общий корпус, доступный каждому пользователю;
   - `Документы проекта` — приватные файлы, доступные всем чатам проекта;
   - `Документы чата` — приватные файлы только открытой ветки.

   Это основной реестр загруженных файлов; возле каждого заголовка показано их
   количество. Для каждого файла видны исходное имя, дата загрузки, состояние
   версии и статус обработки:

   - `queued` — задача ожидает worker;
   - `processing` — идёт извлечение текста/индексация;
   - `ready` — файл доступен retrieval;
   - `failed` — индексация завершилась ошибкой;
   - `cancelled` — задача отменена.

8. Для `ready` проверьте ненулевое число чанков. Нулевое значение означает,
   что текст не извлечён или реестр ещё не обновился.
9. Нажмите имя документа в левой панели, чтобы открыть или скачать именно
   исходный файл. Техническая панель справа используется для новой загрузки и
   показывает только краткий счётчик, чтобы не дублировать реестр.
10. Чтобы удалить приватный документ, нажмите кнопку с корзиной справа от его
    строки и подтвердите действие. Документ сразу исчезает из доступной области
    и перестаёт участвовать в новых ответах; удаление чанков из Qdrant и BM25 и
    исходного файла выполняется через ту же последовательную очередь, что и
    индексация. Действие необратимо. Общий документ может удалить только
    администратор, потому что это влияет на всех пользователей.

Если после подтверждения показано сообщение, что документ скрыт, но очередь
очистки недоступна, не загружайте тот же файл повторно. Он уже исключён из
поиска, однако администратору нужно повторить физическую очистку по job ID.

Тот же выбор области доступен в блоке `База знаний` технической панели. Кнопка
`+` рядом с вопросом предназначена для обычной ежедневной работы, а правая
панель — для диагностики и расширенных настроек.

### Изображения и OCR

Изображения распознаются локально на сервере с помощью OCR на русском и
английском языках. После индексации распознанный текст участвует в поиске как
текст обычного документа, а источником остаётся исходный файл изображения.

OCR хорошо подходит для сканов страниц, фотографий табличек, подписей,
печатного текста и снимков экрана. Это не полноценное визуальное рассуждение:
система не гарантирует понимание графиков, схем, расположения объектов, почерка
и формул сложной вёрстки. Для лучшего результата используйте ровное изображение
без бликов, с высоким контрастом и достаточным разрешением. Если формула важна,
приложите также текстовую расшифровку или исходный документ.

Имена на диске уникализируются, но UI и источники показывают исходное имя.
Повторная загрузка файла создаёт отдельную запись. Если редакции различаются,
добавляйте дату/версию в имя и явно указывайте приоритет в памяти проекта.

Все документы, находившиеся в системе до введения персональных учётных записей,
перенесены в общий корпус. Обычный пользователь не может сделать новый файл
общим через проектную форму загрузки; публикация в общий корпус — отдельное
административное действие. Удаление или замена общего документа влияет на всех
пользователей и должно выполняться только после проверки новой редакции.

Рядом с каждым документом система показывает время загрузки и состояние версии.
Сравнение версий выполняется в пределах соответствующего корпуса: приватные
редакции проекта не раскрываются другим пользователям, а общие сравниваются с
общими:

- `Версия не указана` — в имени или метаданных нет сравнимой редакции;
- `Версия 1.4 · последняя из загруженных` — среди файлов этого проекта версия
  новее не найдена;
- `Есть новее: ...` — в том же проекте распознана более высокая версия того же
  семейства документов.

Можно спросить: «Какие регламенты у нас есть?», «С чем мы сейчас работаем?»,
«Когда загружен документ?» или «Есть ли более актуальная версия?». Эти вопросы
обрабатываются непосредственно по реестру PostgreSQL и не зависят от того,
нашёлся ли подходящий текстовый чанк.

Дата загрузки показывает появление файла в RAG, а не дату утверждения документа.
Система сравнивает только явно обозначенные версии уже загруженных файлов и не
проверяет внешний реестр, СЭД или сайт издателя. Если версия не указана, она не
будет объявлена актуальной автоматически. Для надёжного сравнения используйте
имена вида `Регламент установки v1.4.docx` или `Регламент_2026-09-01.pdf`.

### Как подготовить документ для лучшего качества

- Используйте настоящие заголовки Word или Markdown, а не только жирный текст.
- Если загружаете скан, проверьте резкость, ориентацию страницы и контраст.
- Для PDF проверьте, что текст выделяется мышью.
- Сохраняйте обозначения формул рядом с расшифровкой переменных и единицами.
- Не объединяйте десятки независимых документов в один огромный PDF.
- Удаляйте дубли, черновики и устаревшие редакции либо явно маркируйте их.
- Для таблиц добавляйте заголовки столбцов и единицы измерения.

## 7. Как задавать вопросы, чтобы получать ответы 9/10

Хороший вопрос задаёт объект, действие, период/редакцию и желаемую форму ответа.

Перед поиском система отдельно определяет смысл запроса: сохраняет обозначения
вроде `1 ЦК`, `6ЦК`, номера пунктов и названия сущностей, исправляет очевидные
опечатки в обычных словах и раскладывает составной вопрос на части. Поэтому
запрос `что такое 6ЦК и ак она рассчитывается` должен быть понят как просьба
дать определение и порядок расчёта 6 ЦК, а не как буквальный поиск слова `ак`.
Если опечатка меняет специальный термин или номер пункта, система не угадывает
молча: уточните обозначение в следующем сообщении.

Для вопросов о расчёте retrieval ищет отдельно определение, условия применения,
формулы, параметры и связанные составляющие в нескольких документах. Ответ
должен объединять только согласующиеся фрагменты и ставить источник возле того
утверждения, которое он подтверждает. Откройте `Sources`: там должны быть все
документы, реально использованные в тексте ответа. `Debug` может показывать
больше найденных кандидатов, но они не считаются использованными источниками,
пока на них нет ссылки в ответе.

Вопросы вида `В каких документах фигурирует 1 ЦК?` работают как положительный
список. Система перечисляет только документы с подтверждённым прямым
упоминанием искомой категории. Она не должна добавлять документы, где термина
нет, и объяснять их отсутствие. Название семейства вроде `1-6 ЦК` само по себе
не считается доказательством: в выбранном разделе должно быть прямое
упоминание нужной категории.

Вместо:

```text
Что тут написано?
```

Спросите:

```text
По документам этого проекта перечисли обязательные шаги ввода параметра в
эксплуатацию. Для каждого шага укажи роль исполнителя, входные данные,
результат и источник. Если данных не хватает, перечисли пробелы отдельно.
```

Для сравнения:

```text
Сравни требования редакций 2025 и 2026 годов только по срокам согласования.
Сделай таблицу: пункт, старая редакция, новая редакция, практическое изменение,
источник. Не объединяй пункты с разными основаниями.
```

Для формул:

```text
Покажи точную формулу расчёта ИВ0 из документа, затем расшифруй каждую переменную,
единицы измерения и ограничения применимости. Не подставляй значения, которых нет.
```

Для пошаговой инструкции:

```text
Как создать параметр? Дай последовательность действий по интерфейсу, включая
обязательные поля, проверки и ожидаемый результат каждого шага.
```

Если ответ слишком общий, не начинайте новый чат: уточните «раскрой пункт 3» или
«а по какой формуле?». Система добавит к retrieval последний содержательный
вопрос этого же чата, поэтому предмет разговора не потеряется.

## 8. История, обновление страницы и параллельные чаты

Пользовательские и ассистентские сообщения хранятся в PostgreSQL. При отправке
вопроса сервер сразу создаёт ассистентское сообщение со статусом `running`.
История, проекты и сообщения отбираются по текущей учётной записи: пользователь
не может открыть чужую ветку подменой идентификатора в URL или API-запросе.

Если обновить страницу во время генерации:

1. браузер перестанет ждать старый HTTP-ответ;
2. серверная задача продолжит работу;
3. даже при рестарте API задача останется в Redis/PostgreSQL и будет выполнена
   отдельным worker-процессом;
4. после загрузки страницы история перечитается из PostgreSQL;
5. интерфейс будет опрашивать сервер, пока ответ имеет статус `running`;
6. готовый ответ, его источники и формулы появятся автоматически со статусом
   `complete` или `error`.

Если вы вернулись слишком быстро и всё ещё видите `running`, просто подождите:
переоткрывать чат не требуется. Не отправляйте тот же вопрос многократно: это
создаст несколько полноценных генераций.

Можно одновременно запустить по одному запросу в разных чатах. В одном и том же
чате дождитесь завершения текущего ответа, чтобы порядок реплик оставался
однозначным. Пока есть активные генерации, глобальная смена модели/flow/системного
профиля блокируется: иначе два ответа могли бы строиться в разных режимах.

## 9. Как читать ответ

Ответ может содержать обычный Markdown, списки, таблицы, код и формулы.

- Строчная формула записывается между `$...$`, например `$E=mc^2$`.
- Отдельная формула — между `$$...$$`.
- Если нормативный документ задаёт расчёт словами, система может вывести
  проверенное равенство — например, представить ИВ0 как разность объёма по УДГ
  и объёма по плановому ДГ, — но только когда обе величины однозначно названы в
  найденном правиле. Ни одна неизвестная переменная или числовое значение не
  достраивается автоматически.
- Если формула выглядит как сырой LaTeX, сообщите вопрос, источник и браузер.
- Не копируйте визуально отрисованную формулу как изображение, если нужна
  машинная обработка: используйте исходный текст ответа.

В панели источников показываются только документы и ориентиры, которые реально
процитированы в ответе. Проверьте:

- исходное имя документа;
- понятный ориентир: страницу, раздел, главу, пункт или приложение;
- ссылку, открывающую исходный документ.

Внутренний номер чанка, UUID хранения, score и технический preview не входят в
пользовательский контракт ответа и не показываются в панели источников. Для
диагностики администратор использует отдельный retrieval-контекст во вкладке
`Debug`, а не пользовательскую цитату.

Ссылка вида `Источник: Руководство.docx — раздел «Запуск»` внутри ответа
кликабельна и открывает документ. Та же ссылка повторяется в панели
`Sources`/«Источники». Раздел `Документы проекта`/`Документы чата` слева — это
отдельный реестр всех загруженных файлов текущей области, включая дату, версию
и статус обработки. Старые ответы с техническим UUID автоматически
отображаются в новом виде после обновления UI.

## 10. Что делать при противоречии или отсутствии ответа

Если документы противоречат друг другу, попросите систему вывести оба положения
с отдельными источниками. Проверьте дату, статус, область действия и приоритет
документов самостоятельно.

Если система пишет, что данных недостаточно:

1. убедитесь, что нужный файл имеет статус `ready`;
2. проверьте, что файл загружен в правильный проект;
3. задайте более точные термины, номер пункта или обозначение;
4. проверьте качество OCR/извлечения текста;
5. откройте новый чат только если текущая история действительно уводит вопрос в
   другую тему;
6. не просите модель «догадаться» для критического результата.

## 11. Режимы обработки

| Режим | Когда использовать |
| --- | --- |
| Python | Основной проверенный режим; точный section-aware retrieval и генерация |
| Rust | Диагностика/сравнение альтернативного retrieval и Rust-генерации |
| Hybrid | Python evidence дополняется Rust-кандидатами, ответ формирует Python LLM adapter |

Если нет специальной причины, используйте Python. Переключение режима очищает
общий кэш ответов, поэтому первый повторный запрос будет медленнее.

## 12. Кэш

Кэш точный: он возвращает ранее сгенерированный ответ только для совпадающего
набора вопроса, контекстуализированного retrieval-запроса, модели, системного
профиля, памяти проекта и области документов. Похожие формулировки не считаются
одним запросом. После индексации корпус меняется, и ответы инвалидируются.

Признак `from_cache` означает повторное использование проверенного результата,
а не пропуск авторизации или retrieval-изоляции. Идентичный вопрос в другом
проекте, у другого пользователя или при другой области знаний не может получить
ответ из несовместимого кэша.

## 13. Конфиденциальность и безопасное использование

- Загружайте только документы, разрешённые для этой среды и аудитории.
- Считайте общий документ доступным каждому зарегистрированному пользователю
  среды. Конфиденциальные материалы загружайте только в свой проект.
- Не вставляйте пароли, API-ключи, приватные ключи и bearer-токены.
- Перед публикацией ответа проверьте, не содержит ли он персональные данные.
- Не переносите источник из одного проекта в другой обходными способами.
- Не воспринимайте инструкции внутри документа как команды системе: подозрительные
  prompt-injection фрагменты фильтруются, но документ остаётся недоверенным вводом.
- Для юридических, финансовых, медицинских и производственно-безопасностных
  решений обязательно привлекайте уполномоченного специалиста.

## 14. Типовые проблемы

| Симптом | Что проверить |
| --- | --- |
| Не удаётся зарегистрироваться | корректность email, длину пароля и отсутствие совпадения с частью email |
| Не удаётся войти | раскладку клавиатуры; после серии ошибок подождать окончание временной блокировки |
| Проекты не загрузились | сеть, срок сессии, затем один refresh |
| Браузер показывает системное окно логина/пароля | сообщить администратору: внешний Basic Auth на этом адресе не используется |
| После обновления открылась страница входа | сессия истекла/отозвана; войти снова, незавершённая генерация продолжит работу |
| В проекте виден неожиданный общий документ | проверить область знаний; при необходимости включить `Только документы проекта` |
| Не видно общего документа | проверить статус файла и что выбран режим `Документы проекта и общие` |
| Видно имя чужого приватного проекта/файла | прекратить работу и немедленно сообщить администратору — это нарушение изоляции |
| Не видно старые чаты проекта | нажать `Ещё N`; сворачивание списка ничего не удаляет |
| Документ долго `queued` | доступность ingestion worker/Redis; сообщить job id администратору |
| Документ `failed` | формат, размер, наличие текстового слоя/OCR |
| Документ удалён, но показана ошибка очереди очистки | не загружать дубль; передать администратору имя документа, время и job ID — документ уже исключён из новых ответов |
| Ответ остался `running` | подождать, переоткрыть чат; при длительном статусе сообщить время/chat id |
| Нет источника | ответ мог быть служебным/ошибкой; для фактического ответа источник обязателен |
| Источник из неверного проекта | прекратить использование ответа и сообщить оба project/chat id |
| Формула не отрисовалась | проверить `$`/`$$`, браузер, прислать исходный вопрос без секретов |
| Повторный ответ устарел | проверить статус новой загрузки и память проекта; попросить администратора проверить cache invalidation |

## 15. Что приложить к обращению администратору

Передайте минимум данных, достаточный для воспроизведения, без содержимого
закрытых документов:

- дата и точное время с часовым поясом;
- URL среды;
- название проекта и чата (или их ID, если доступны);
- исходный вопрос;
- имя документа и его статус;
- ожидаемое и фактическое поведение;
- браузер/версия;
- `X-Request-ID`/trace ID или job ID;
- скриншот без токенов, персональных данных и лишних вкладок.

## 16. Короткий чек-лист качественного ответа

- [ ] выбран правильный проект и чат;
- [ ] нужные документы имеют статус `ready`;
- [ ] указана редакция/период/объект;
- [ ] ответ прямо отвечает на вопрос;
- [ ] у ключевых утверждений есть подходящие источники;
- [ ] открыты и проверены критические разделы;
- [ ] формулы, переменные и единицы согласованы;
- [ ] противоречия и пробелы не скрыты;
- [ ] в ответе нет данных, которых не было в источниках;
- [ ] итог проверен ответственным специалистом, если цена ошибки высока.
