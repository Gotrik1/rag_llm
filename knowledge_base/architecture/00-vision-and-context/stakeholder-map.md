
# КАРТА СТЕЙКХОЛДЕРОВ ПРОЕКТА «10X»

*Версия: 1.0*
*Статус: DRAFT

## 1. Цель документа

Обеспечить единое понимание состава заинтересованных сторон, их ожиданий, уровня влияния и степени вовлеченности в разработку и развитие продукта «10X». Используется для:

- Планирования коммуникаций;
- Управления ожиданиями;
- Митигации рисков саботажа или неверной интерпретации требований.

## 2. Матрица классификации стейкхолдеров (Власть / Интерес)

### 2.1. Модель Менделоу (Power/Interest Grid)

| **Квадрант**                                         | **Стейкхолдеры**                                                                                                         | **Стратегия**                             |
|------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------|-------------------------------------------|
| **Высокая власть, Высокий интерес** (Manage Closely) | Владелец бизнеса (заказчик)<br>Руководитель продукта (PO)                                                                | Активное вовлечение, личные встречи, демо |
| **Высокая власть, Низкий интерес** (Keep Satisfied)  | Финансовый директор / Инвестор<br>Юридический департамент (GDPR/152-ФЗ)<br>Технический директор (архитектура)            | Регулярная отчетность, контроль рисков    |
| **Низкая власть, Высокий интерес** (Keep Informed)   | Категорийные менеджеры<br>РОПы пилотных клиентов<br>Аналитики внутренние                                                 | Демо, рассылки, чаты поддержки            |

## 3. Детальный профиль стейкхолдеров

### 3.1. Внутренние стейкхолдеры (Команда разработки и владельцы продукта)

#### **1. Владелец бизнеса / Инициатор (Product Owner)**

| Атрибут               | Значение                                                                                                                                         |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| **Роль**              | Лицо, принимающее стратегические решения. Сформулировал концепцию «10X».                                                                         |
| **Интересы**          | Рост чистой прибыли клиентов, уникальное позиционирование, отстройка от конкурентов.                                                             |
| **Боли**              | Текущие сервисы не отвечают на вопрос «Что делать?». Боится, что разработка уйдет в «еще один дашборд».                                          |
| **Влияние**           | Абсолютное вето на требования.                                                                                                                   |
| **Канал связи**       | Еженедельный стратегический синк. Демо каждые 2 недели.                                                                                          |
| **Уровень вовлечения**| Очень высокий (спонсор проекта).                                                                                                                 |

#### **2. Руководитель разработки / Архитектор**

| Атрибут               | Значение                                                                                             |
|-----------------------|------------------------------------------------------------------------------------------------------|
| **Роль**              | Отвечает за техническую реализацию, интеграцию с API WB, масштабирование.                            |
| **Интересы**          | Стабильность системы, отсутствие технического долга, соблюдение NFR.                                 |
| **Боли**              | Ограничения API Wildberries / OZON (лимиты, нестабильность данных).                                  |
| **Влияние**           | Высокое (оценка трудоемкости сложных фич).                                                           |
| **Канал связи**       | Daily stand-up, техспецификации.                                                                     |
| **Уровень вовлечения**| Полный.                                                                                              |

#### **3. Финансовый директор / Инвестор**

| Атрибут               | Значение                                                                                             |
|-----------------------|------------------------------------------------------------------------------------------------------|
| **Роль**              | Контролирует бюджет разработки, окупаемость, юнит-экономику продукта.                                |
| **Интересы**          | Скорость выхода на рынок (TTM), LTV клиента, стоимость привлечения (CAC).                            |
| **Боли**              | Долгая окупаемость, сложность монетизации функций (за что брать деньги).                             |
| **Влияние**           | Высокое (финансирование).                                                                            |
| **Канал связи**       | Ежемесячный отчет по метрикам продукта.                                                              |
| **Уровень вовлечения**| Средний, повышается на этапе релиза.                                                                 |

#### **4. Внутренний аналитик (Системный/Бизнес-аналитик)**

| Атрибут               | Значение                                                                                             |
|-----------------------|------------------------------------------------------------------------------------------------------|
| **Роль**              | Трансляция потребностей пользователей в технические требования.                                      |
| **Интересы**          | Прозрачность логики расчетов, корректность формул (прибыль, ДРР, оборачиваемость).                   |
| **Боли**              | Размытые формулировки от владельца («сделайте, как в экселе, только лучше»).                         |
| **Влияние**           | Среднее, но высокое на этапе спецификации.                                                           |
| **Канал связи**       | Ежедневная работа в бэклоге.                                                                         |
| **Уровень вовлечения**| Полный.                                                                                              |

### 3.2. Внешние стейкхолдеры (Клиенты и Партнеры)

#### **5. Категорийный менеджер (Целевой пользователь)**

| Атрибут               | Значение                                                                                             |
|-----------------------|------------------------------------------------------------------------------------------------------|
| **Роль**              | Ключевой оператор системы. Работает с десятками/сотнями SKU ежедневно.                               |
| **Интересы**          | Скорость загрузки, понятные алерты, автоматизация рутины (поставки, ставки).                         |
| **Боли**              | Ненавидит «еще одну таблицу». Нужны конкретные действия, а не графики.                               |
| **Влияние**           | Среднее. Если пользователь не примет систему, владелец не продлит подписку.                          |
| **Канал связи**       | UX-исследования, чат поддержки, интервью.                                                            |
| **Уровень вовлечения**| Высокий на этапе тестирования (ранние пташки).                                                       |

#### **6. РОП (Руководитель отдела продаж)**

| Атрибут               | Значение                                                                                             |
|-----------------------|------------------------------------------------------------------------------------------------------|
| **Роль**              | Контролирует выполнение плана, мотивацию команды.                                                    |
| **Интересы**          | Объективные KPI для премирования, сводные отчеты по команде.                                         |
| **Боли**              | Хаос в работе менеджеров, невозможность быстро увидеть «кто просел».                                 |
| **Влияние**           | Высокое (инициирует покупку корпоративных лицензий).                                                 |
| **Канал связи**       | Вебинары, презентации РНП, кейсы.                                                                    |
| **Уровень вовлечения**| Средний (покупатель, но не ежедневный юзер).                                                         |

#### **7. Владелец бизнеса клиента (CEO селлера)**

| Атрибут               | Значение                                                                                             |
|-----------------------|------------------------------------------------------------------------------------------------------|
| **Роль**              | Принимает решение о покупке, платит деньги.                                                          |
| **Интересы**          | Видит картину целиком («Рука на пульсе»), уверенность в завтрашнем дне.                              |
| **Боли**              | Не понимает, почему прибыль падает, если продажи растут.                                             |
| **Влияние**           | Критическое для продаж.                                                                              |
| **Канал связи**       | Лендинг, кейсы, Telegram-дайджест (рассылка).                                                        |
| **Уровень вовлечения**| Низкий в разработку, высокий в принятие решения о покупке.                                           |

#### **8. Представители Wildberries и OZON  (API / Партнерский отдел)**

| Атрибут                | Значение                                            |
| ---------------------- | --------------------------------------------------- |
| **Роль**               | Владелец платформы, контролер доступа к данным.     |
| **Интересы**           | Соблюдение оферты, отсутствие DDOS-нагрузки на API. |
| **Боли**               | Некорректные парсеры, создающие нагрузку.           |
| **Влияние**            | Очень высокое (могут заблокировать токены).         |
| **Канал связи**        | Официальная техподдержка WB, мониторинг changelog.  |
| **Уровень вовлечения** | Минимальный (только при инцидентах).                |

#### **9. Конкуренты (MPStats, SellerFox, AutoMP и др.)**

| Атрибут                | Значение                                                              |
| ---------------------- | --------------------------------------------------------------------- |
| **Роль**               | Рыночная среда.                                                       |
| **Интересы**           | Копирование успешных фич «10X».                                       |
| **Боли**               | Потеря доли рынка.                                                    |
| **Влияние**            | Косвенное (влияет на приоритеты фич через конкурентное преимущество). |
| **Канал связи**        | Мониторинг релизов, форумы селлеров.                                  |
| **Уровень вовлечения** | Мониторинг.                                                           |

## 5. Коммуникационная стратегия (Уровни взаимодействия)

### Уровень 1. Стратегический (Спонсоры и ТОП-менеджмент)

**Частота:** 1 раз в 2 недели  
**Формат:** Демо готовых инкрементов, обновление роадмапа  
**Ответственный:** Product Owner  
**Цель:** Подтверждение стратегического курса, демонстрация ценности

### Уровень 2. Операционный (Команда разработки)

**Частота:** Ежедневно / Еженедельно  
**Формат:** Daily, планирование спринта, груминг  
**Ответственный:** Scrum Master / Team Lead  
**Цель:** Синхронизация разработки, уточнение требований

### Уровень 3. Пользовательский (Клиенты)

**Частота:** Еженедельно / По запросу  
**Формат:** Интервью, опросы, анализ тикетов  
**Ответственный:** Продуктовый аналитик  
**Цель:** Валидация гипотез, сбор инсайтов

### Уровень 4. Информационный (Широкая аудитория)

**Частота:** Ежемесячно  
**Формат:** Блог, Telegram-канал продукта, релиз-ноуты  
**Ответственный:** Маркетинг  
**Цель:** Формирование лояльности, информирование об обновлениях

## 6. Риски, связанные со стейкхолдерами

| Риск                                                                 | Владелец риска       | Митигация                                                                            |
| -------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------ |
| **Владелец бизнеса меняет требования каждую неделю**                 | PO                   | Внедрение жесткого бэклог-менеджмента. Изменения только через formal change request. |
| **Категорийные менеджеры саботируют внедрение**                      | Аналитик             | Вовлечение амбассадоров из числа пользователей на этапе бета-теста.                  |
| **Wildberries блокирует API из-за высокой нагрузки**                 | Архитектор           | Кэширование, асинхронные очереди, ретраи с экспоненциальной задержкой.               |
| **OZON блокирует API из-за высокой нагрузки**                        | Архитектор           | Кэширование, асинхронные очереди, ретраи с экспоненциальной задержкой.               |
| **РОП клиента ожидает функционал, не запланированный в MVP**         | Менеджер по продажам | Четкое документирование границ релиза (см. Vision & Scope).                          |
| **Инвестор замораживает бюджет из-за долгого выхода на окупаемость** | Владелец бизнеса     | Быстрый запуск MVP с платной подпиской на базовых тарифах.                           |

## 7. Заключение

Карта стейкхолдеров является «живым документом» и пересматривается:

- При появлении нового класса пользователей (например, бренды-производители);
- При выходе на новые маркетплейсы (Ozon);
- При смене бизнес-модели.
