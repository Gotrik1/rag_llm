## 1. Базовые метрики

### 1.1. Средний чек

**С учетом СПП (скидки):**

```sql
avg_check_with_spp = SUM(avg_price_with_spp * orders_count) / NULLIF(SUM(orders_count), 0)
```

**Без учета СПП:**

```sql
avg_check_without_spp = SUM(avg_price_without_spp * orders_count) / NULLIF(SUM(orders_count), 0)
```

**Формула цены со скидкой:**

```sql
avg_price_with_spp = avg_price * (1 - spp_percent)
```

**Пример:**

- Базовая цена: 1000 руб
- СПП скидка: 20% (0.20)
- Цена со скидкой: 1000 * (1 - 0.20) = 800 руб

---

### 1.2. Процент СПП (средняя скидка)

```sql
spp_percent = AVG(spp_percent) FILTER (WHERE orders_count > 0)
```

**Важно:** Считается только по дням с заказами!

---

### 1.3. Процент выкупа

```sql
buyout_percent = buyouts_count / NULLIF(orders_count, 0)
```

**Пример:**

- Заказы: 100 шт
- Выкупы: 80 шт
- Процент выкупа: 80 / 100 = 0.80 (80%)

---

### 1.4. Прогнозируемые выкупы

```sql
expected_buyouts_count = orders_count * buyout_percent
expected_buyouts_sum = orders_sum_rub * buyout_percent
```

**Логика:** Используется средний процент выкупа для прогноза незавершенных заказов.

---

### 1.5. Локализация (процент локальных заказов)

```sql
localization_percent = SUM(orders_count_local) / NULLIF(SUM(orders_count), 0)
```

**Где:**

- `orders_count_local` - заказы из локального региона (например, тот же город, что и склад)

## 2. Прибыль и маржинальность

### 2.1. Прибыль БЕЗ рекламы

```sql
profit_without_adv = buyouts_sum_rub - sebes_rub * buyouts_count - commission
```

**Где:**

- `buyouts_sum_rub` - выручка от выкупленных товаров
- `sebes_rub` - себестоимость единицы товара
- `buyouts_count` - количество выкупов
- `commission` - комиссия маркетплейса

**Пример:**

- Выручка: 100 000 руб
- Себестоимость: 30 руб × 800 шт = 24 000 руб
- Комиссия: 15 000 руб
- Прибыль без рекламы: 100 000 - 24 000 - 15 000 = **61 000 руб**

---

### 2.2. Прибыль С рекламой

```sql
profit_with_adv = profit_without_adv - adv_sum
```

**Или полная формула:**

```sql
profit_with_adv = buyouts_sum_rub - sebes_rub * buyouts_count - commission - adv_sum
```

**Пример:**

- Прибыль без рекламы: 61 000 руб
- Расходы на рекламу: 10 000 руб
- Прибыль с рекламой: 61 000 - 10 000 = **51 000 руб**

---

### 2.3. Маржинальность БЕЗ рекламы

```sql
marg_without_adv_percent = SUM(profit_without_adv) / NULLIF(SUM(expected_buyouts_sum_rub), 0)
```

**Пример:**

- Прибыль без рекламы: 61 000 руб
- Прогнозируемая выручка: 100 000 руб
- Маржинальность: 61 000 / 100 000 = **0.61 (61%)**

---

### 2.4. Маржинальность С рекламой

```sql
marg_with_adv_percent = SUM(profit_with_adv) / NULLIF(SUM(expected_buyouts_sum_rub), 0)
```

**Пример:**

- Прибыль с рекламой: 51 000 руб
- Прогнозируемая выручка: 100 000 руб
- Маржинальность: 51 000 / 100 000 = **0.51 (51%)**

---

## 3. Реклама (ДРР)

### 3.1. ДРР от заказов (adv_percent)

```sql
adv_percent = SUM(adv_sum) / NULLIF(SUM(orders_sum_rub), 0)
```

**Расшифровка:**

- ДРР = расходы на рекламу / выручка от заказов

**Пример:**

- Реклама: 10 000 руб
- Выручка от заказов: 120 000 руб
- ДРР: 10 000 / 120 000 = **0.083 (8.3%)**

---

### 3.2. ДРР от выкупов (adv_percent_by_buyout)

```sql
adv_percent_by_buyout = SUM(adv_sum) / NULLIF(SUM(buyouts_sum_rub), 0)
```

**Пример:**

- Реклама: 10 000 руб
- Выручка от выкупов: 100 000 руб
- ДРР от выкупов: 10 000 / 100 000 = **0.10 (10%)**

---

### 3.3. ДРР от прогнозируемых выкупов

```sql
adv_percent_by_expected_buyout = SUM(adv_sum) / NULLIF(SUM(expected_buyouts_sum_rub), 0)
```

**Применение:**

- Используется для более точной оценки окупаемости рекламы
- Учитывает незавершенные заказы

---

## 4. КРРР (Коэффициент рентабельности)

### 4.1. Формула КРРР

```sql
krrr_percent = CASE 
    WHEN SUM(profit_without_adv) <= 0 THEN 0
    WHEN SUM(profit_with_adv) < 0 THEN 0
    ELSE LEAST(SUM(profit_with_adv) / NULLIF(SUM(profit_without_adv), 0), 1)
END
```

**Расшифровка:**

- КРРР = прибыль с рекламой / прибыль без рекламы
- Показывает, какую долю прибыли оставляем после рекламы

**Интерпретация:**

- **КРРР = 1.0 (100%)** - реклама бесплатная (идеал, недостижимый)
- **КРРР = 0.8 (80%)** - на рекламу уходит 20% прибыли (отлично)
- **КРРР = 0.5 (50%)** - на рекламу уходит 50% прибыли (приемлемо)
- **КРРР < 0.5 (< 50%)** - на рекламу уходит > 50% прибыли (плохо)
- **КРРР = 0** - убыточная реклама

**Пример:**

- Прибыль без рекламы: 61 000 руб
- Прибыль с рекламой: 51 000 руб
- КРРР: 51 000 / 61 000 = **0.836 (83.6%)**

**Важные условия:**

1. Если `profit_without_adv <= 0` → КРРР = 0 (товар изначально убыточен)
2. Если `profit_with_adv < 0` → КРРР = 0 (реклама делает товар убыточным)
3. КРРР ограничен сверху значением 1.0 (не может быть > 100%)

## 5. ABC-анализ

### 5.1. Базовые метрики для ABC

```sql
-- Для каждого товара за месяц:
abc_buyouts_sum_rub = SUM(expected_buyouts_sum_rub)
abc_profit_without_adv = SUM(profit_without_adv)
```

---

### 5.2. ROI до ДРР (рентабельность инвестиций)

```sql
abc_roi_do_drr = CASE 
    WHEN SUM(sebes_rub * expected_buyouts_count) > 0 THEN 
        SUM(profit_without_adv) / SUM(sebes_rub * expected_buyouts_count)
    ELSE 0 
END
```

**Расшифровка:**

- ROI = прибыль без рекламы / себестоимость товаров

**Пример:**

- Прибыль без рекламы: 61 000 руб
- Себестоимость: 30 руб × 800 шт = 24 000 руб
- ROI: 61 000 / 24 000 = **2.54 (254%)**

**Интерпретация:**

- ROI = 2.54 означает, что на каждый рубль себестоимости получаем 2.54 рубля прибыли

---

### 5.3. КРРР для ABC

```sql
abc_krrr = CASE  
    WHEN SUM(profit_without_adv) > 0 THEN 
        SUM(profit_with_adv) / SUM(profit_without_adv)
    ELSE 0 
END
```

*(см. раздел 4.1 для детального описания)*

---

### 5.4. Накопительная доля выручки

```sql
running_percent_buyouts = SUM(abc_buyouts_sum_rub) OVER (ORDER BY abc_buyouts_sum_rub DESC) 
                        / NULLIF(SUM(abc_buyouts_sum_rub) OVER (), 0)
```

**Логика:**

1. Сортируем товары по убыванию выручки
2. Считаем накопительную сумму выручки
3. Делим на общую выручку

**Пример:**

- Товар 1: 100 000 руб → накопительная доля 100/300 = 33%
- Товар 2: 150 000 руб → накопительная доля 250/300 = 83%
- Товар 3: 50 000 руб → накопительная доля 300/300 = 100%

---

### 5.5. Накопительная доля прибыли

```sql
running_percent_profit = SUM(abc_profit_without_adv) OVER (ORDER BY abc_profit_without_adv DESC) 
                       / NULLIF(SUM(abc_profit_without_adv) OVER (), 0)
```

*(аналогично running_percent_buyouts)*

---

### 5.6. Категоризация по метрикам

**По выручке:**

```sql
category_buyouts = CASE 
    WHEN running_percent_buyouts <= 0.8 THEN 'A'
    WHEN running_percent_buyouts <= 0.95 THEN 'B'
    ELSE 'C'
END
```

**По прибыли:**

```sql
category_profit = CASE 
    WHEN running_percent_profit <= 0.8 THEN 'A'
    WHEN running_percent_profit <= 0.95 THEN 'B'
    ELSE 'C'
END
```

**По ROI:**

```sql
category_roi = CASE 
    WHEN abc_roi_do_drr > 0.7 THEN 'A'
    WHEN abc_roi_do_drr > 0.5 THEN 'B'
    ELSE 'C'
END
```

**По КРРР:**

```sql
category_krrr = CASE 
    WHEN abc_krrr > 0.8 THEN 'A'
    WHEN abc_krrr >= 0.5 THEN 'B'
    ELSE 'C'
END
```

---

### 5.7. Комплексная оценка (ABC Score)

```sql
abc_score = 
    (CASE category_buyouts WHEN 'A' THEN 100 WHEN 'B' THEN 50 WHEN 'C' THEN 15 ELSE 0 END) * 0.2 +
    (CASE category_profit  WHEN 'A' THEN 100 WHEN 'B' THEN 50 WHEN 'C' THEN 15 ELSE 0 END) * 0.2 +
    (CASE category_roi     WHEN 'A' THEN 100 WHEN 'B' THEN 50 WHEN 'C' THEN 15 ELSE 0 END) * 0.35 +
    (CASE category_krrr    WHEN 'A' THEN 100 WHEN 'B' THEN 50 WHEN 'C' THEN 15 ELSE 0 END) * 0.25
```

**Веса метрик:**

- Выручка: 20%
- Прибыль: 20%
- ROI: 35% (наибольший вес)
- КРРР: 25%

**Максимальный балл:** 100

---

### 5.8. Итоговая категория ABC

```sql
abc_category = CASE 
    WHEN abc_score > 80 THEN 'Удерживать'
    WHEN abc_score > 60 THEN 'ТОП Развивать' 
    WHEN abc_score >= 40 THEN 'Развивать' 
    ELSE 'Сливать'
END
```

**Рекомендации:**

- **Удерживать (>80):** Лучшие товары, поддерживать текущую стратегию
- **ТОП Развивать (60-80):** Высокий потенциал, увеличить инвестиции
- **Развивать (40-60):** Средний потенциал, оптимизировать
- **Сливать (<40):** Низкая эффективность, рассмотреть вывод из ассортимента

## 6. Остатки и запас дней

### 6.1. Запас дней по заказам

```sql
stocks_enough_for = stocks / NULLIF(orders_dyn, 0)
```

**Где:**

- `stocks` - текущие остатки (шт)
- `orders_dyn` - динамика заказов (средняя скорость продаж в день)

**Пример:**

- Остатки: 300 шт
- Динамика: 20 шт/день
- Запас дней: 300 / 20 = **15 дней**

---

### 6.2. Запас дней по выкупам с учетом %

```sql
stocks_enough_for_with_buyout_percent = stocks_total / NULLIF(expected_buyouts_dyn, 0)
```

**Где:**

- `stocks_total` - общие остатки (на складе + в пути)
- `expected_buyouts_dyn` - динамика прогнозируемых выкупов

**Более точная оценка**, учитывает:

1. Товары в пути к складу
2. Процент выкупа

## 7. Прогнозы и планы

### 7.1. Прогноз на месяц (экстраполяция)

```sql
-- Доля прошедших дней месяца
month_part = EXTRACT(DAY FROM date_to) / EXTRACT(DAY FROM max_date)

-- Прогноз метрики на месяц
forecast_metric = fact_metric / month_part
```

**Пример:**

- Сегодня 15-е число месяца
- Дней в месяце: 30
- Доля: 15 / 30 = 0.5 (прошло 50% месяца)
- Факт выручки: 50 000 руб
- Прогноз на месяц: 50 000 / 0.5 = **100 000 руб**

---

### 7.2. План на день

```sql
day_plan_metric = plan_month_metric / max_date_count
```

**Где:**

- `max_date_count` - количество дней в месяце

**Пример:**

- План на месяц: 150 000 руб
- Дней в месяце: 30
- План на день: 150 000 / 30 = **5 000 руб/день**

---

### 7.3. Коэффициент выполнения плана

```sql
forecast_ratio = plan_metric / NULLIF(forecast_metric, 0)
```

**Интерпретация:**

- Ratio = 1.0 (100%) - план выполняется точно
- Ratio > 1.0 - прогноз ниже плана (недовыполнение)
- Ratio < 1.0 - прогноз выше плана (перевыполнение)

**Пример:**

- План: 150 000 руб
- Прогноз: 100 000 руб
- Ratio: 150 000 / 100 000 = **1.5 (план выполнен на 67%)**

## 8. Динамика и тренды

### 8.1. Динамика неделя к неделе

```sql
dynamics_metric = week1_metric - week2_metric
```

**Где:**

- `week1` - последние 7 дней
- `week2` - предыдущие 7 дней (8-14 дней назад)

**Пример:**

- Week1 выручка: 35 000 руб
- Week2 выручка: 28 000 руб
- Динамика: 35 000 - 28 000 = **+7 000 руб** (рост на 25%)

---

### 8.2. Органический процент (доля не рекламных визитов)

```sql
organic_percent = (open_card_count - clicks) / NULLIF(open_card_count, 0)
```

**Где:**

- `open_card_count` - общее количество просмотров карточки
- `clicks` - клики из рекламы

**Пример:**

- Просмотры: 1000
- Клики из рекламы: 300
- Органика: (1000 - 300) / 1000 = **0.7 (70%)**

---

### 8.3. Доля источников трафика

**Из поиска (adv_search_percent):**

```sql
adv_search_percent = (clicks_keywords + clicks_search) / NULLIF(open_card_count, 0)
```

**Из полок (adv_polki_percent):**

```sql
adv_polki_percent = clicks_rs_cat / NULLIF(open_card_count, 0)
```

**Внешний трафик (adv_external_percent):**

```sql
adv_external_percent = open_card_count_jam / NULLIF(open_card_count, 0)
```

**Проверка:**

```
organic_percent + adv_search_percent + adv_polki_percent + adv_external_percent ≈ 1.0
```

## 9. Специальные условия и краевые случаи

### 9.1. Товары без себестоимости (not_in_unit)

```sql
-- Если у товара нет себестоимости, обнуляем метрики прибыли/маржи
marg_with_adv_percent = CASE WHEN niu.nm_id IS NULL THEN marg_with_adv ELSE 0 END
profit_with_adv = CASE WHEN niu.nm_id IS NULL THEN profit_with_adv ELSE 0 END
```

**Логика:**

- Без себестоимости невозможно корректно посчитать прибыль
- Такие товары помечаются `isInUnit = false`

---

### 9.2. Защита от деления на ноль

Все формулы используют `NULLIF(divisor, 0)`:

```sql
-- Плохо (может быть ошибка)
result = numerator / denominator

-- Хорошо (защита от деления на 0)
result = numerator / NULLIF(denominator, 0)
```

Если знаменатель = 0, результат будет `NULL` (а не ошибка).

---

### 9.3. Округление

**Денежные значения:** до 0 знаков

```sql
ROUND(value, 0)  -- 1234.56 → 1235
```

**Проценты и коэффициенты:** до 5 знаков

```sql
ROUND(value, 5)  -- 0.12345678 → 0.12346
```
