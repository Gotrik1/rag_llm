# Analytics Engine Bounded Context

## Назначение

Analytics Engine — это Core Domain системы 10X.

Контекст отвечает за:

* расчёт управленческой прибыли,
* формирование RNP,
* анализ экономики SKU,
* учёт соинвеста,
* сопоставление плановых и фактических показателей,
* формирование бизнес-P&L,
* консолидацию аналитики по Workspace.

Именно этот контекст формирует управленческую модель бизнеса и создаёт основную ценность продукта.

---

## Граница контекста

Внутри контекста находятся:

* SKU как бизнес-идентичность товара
* UNIT (экономика единицы)
* Orders
* Buyouts
* Returns
* RNP (оперативная управленческая отчётность)
* Financial Fact
* External Costs
* Planning
* Ads & Search Analytics (в части влияния на прибыль и маржинальность)

В контекст не входят:

* API-токены
* синхронизация данных
* пользователи
* роли
* RBAC
* управление подключениями маркетплейсов

Analytics Engine получает нормализованные данные извне (из Marketplace Integration),
но не управляет источниками данных и не взаимодействует напрямую с API маркетплейсов.

---

## Ubiquitous Language (Единый предметный язык)

Внутри контекста используется единый язык:

* SKU — товарная бизнес-единица
* UNIT — зафиксированная экономика единицы товара
* Order — заказ
* Buyout — подтверждённая реализация
* Return — возврат
* RNP — оперативная управленческая прибыльность
* Financial Fact — официальный финансовый отчёт маркетплейса
* Base Economics — расчёт без учёта соинвеста
* Actual Economics — расчёт с учётом соинвеста
* Plan — плановые показатели
* P&L — итоговый финансовый результат бизнеса

Этот язык является единым внутри контекста и используется всеми его внутренними модулями.

---

## Core Responsibility (Ключевая ответственность контекста)

Контекст отвечает за:

* фиксацию и версионирование UNIT,
* учёт заказов, выкупов и возвратов,
* расчёт прибыли,
* расчёт показателей в двух режимах:

  * без соинвеста (Base),
  * с учётом соинвеста (Actual),
* сопоставление плана и факта,
* агрегацию данных по Workspace,
* формирование управленческой отчётности,
* объединение рекламы, продаж и финансов в единую модель.

Контекст не изменяет операционные данные источника,
а интерпретирует их в рамках собственной управленческой модели.

---

## Инварианты

* Все данные жёстко привязаны к workspace_id.
* История UNIT не переписывается.
* Соинвест не изменяет себестоимость.
* RNP не изменяет исходные операционные данные.
* План не влияет на фактические показатели.
* Financial Fact может отличаться от оперативных расчётов.
* Прибыль может рассчитываться в двух режимах (Base / Actual).
* Контекст не зависит от внутренней модели API маркетплейсов.

---

## Внутренняя модульность (архитектурная оговорка)

Внутри Analytics Engine логически выделяются следующие модули:

* **Reference Data (Справочные данные)**
  Базовые бизнес-сущности и классификаторы.

* **Unit Economics (Юнит-экономика)**
  Расчёт и фиксация экономики единицы товара.

* **Operations (Операции)**
  Учёт заказов (Orders), выкупов (Buyouts) и возвратов (Returns).

* **RNP (Management Reporting — управленческая отчётность)**
  Оперативный расчёт прибыльности.

* **Financial Fact (Финансовый факт)**
  Работа с официальными финансовыми отчётами маркетплейса.

* **Planning (Планирование)**
  Плановые показатели, сезонность, сравнение план/факт.

* **External Costs (Внешние расходы)**
  Расходы вне маркетплейса (логистика, подрядчики, прочее).

* **Ads & Diagnostics (Реклама и диагностика эффективности)**
  Анализ влияния рекламных расходов и поисковых показателей на прибыль.

Несмотря на логическое разделение, данные элементы:

* используют единый язык,
* работают в рамках одной бизнес-цели,
* разделяют идентичность SKU,
* работают внутри одной границы Workspace,
* оперируют единой моделью прибыли.

Поэтому они:

не являются отдельными Bounded Context,
а представляют собой внутренние модули одного Core Domain — Analytics Engine.

---

## Возможность эволюции

При масштабировании системы (разделение команд, выделение сервисов, независимые релизы) данные модули могут быть преобразованы в отдельные Bounded Context.

На текущем этапе архитектуры они остаются частью единого аналитического контекста.
