
# Инвентаризация инфраструктурных компонентов (DRAFT)

## Введение

Этот документ описывает основные [Infrastructure Diagram](../04-physical-architecture/diagrams/infrastructure-components.png), используемые в проекте, включая Nginx, PostgreSQL, Redis, NATS, BullMQ, а также системы мониторинга (Grafana, Loki, Prometheus). Он предоставляет краткое описание ролей и функциональностей каждого компонента в рамках системы.

>**Статус документа: DRAFT**

## Инфраструктурные компоненты

### 1. Nginx Reverse Proxy

**Роль в системе:**
Nginx выполняет роль реверс-прокси, обеспечивая маршрутизацию входящих HTTP/HTTPS запросов и их отправку на соответствующие сервисы. Он также отвечает за SSL-терминацию и маршрутизацию данных между контейнерами.

**Конфигурация:**

* **Контейнер:** Nginx
* **Основные функции:**

  * Обработка и маршрутизация запросов
  * SSL-терминация
  * Управление безопасностью

**Статус:** Данные о текущей конфигурации подлежат уточнению.

---

### 2. PostgreSQL (База данных)

**Роль в системе:**
PostgreSQL используется в проекте как реляционная база данных для хранения данных, таких как информация о маркетплейсах, транзакциях, расчетах и аналитике.

**Конфигурация:**

* **Контейнер:** PostgreSQL
* **Структура базы данных:**

  * public schema
  * shared schema
  * schema_{client_id}

**Статус:** Конфигурация базы данных и стратегия резервного копирования подлежат уточнению.

---

### 3. Redis (Кэширование)

**Роль в системе:**
Redis используется для кэширования данных, управления блокировками и очередями, а также для хранения временных данных в памяти.

**Конфигурация:**

* **Контейнер:** Redis
* **Функции:**

  * Хранение данных в памяти
  * Управление очередями и блокировками
  * Кэширование данных

**Статус:** Стратегия кэширования подлежит уточнению, а также анализируем роль Redis в высоконагруженных операциях.

---

### 4. NATS (Message Broker)

**Роль в системе:**
NATS служит брокером сообщений для асинхронной и синхронной обработки сообщений между сервисами с использованием паттернов pub/sub и request-reply.

**Конфигурация:**

* **Контейнер:** NATS
* **Типы сообщений:**

  * pub/sub
  * request-reply

**Статус:** Конфигурация и маршрутизация сообщений в процессе уточнения.

---

### 5. BullMQ (Очереди задач)

**Роль в системе:**
BullMQ используется для обработки асинхронных задач, включая управление очередями, задачами с отложенным выполнением и приоритетами.

**Конфигурация:**

* **Контейнер:** BullMQ
* **Основные функции:**

  * Обработка очередей задач
  * Обработка асинхронных задач с поддержкой отложенных и приоритетных задач

**Статус:** Ожидается уточнение роли каждой очереди и типы задач, которые обрабатываются в проекте.

---

### 6. Мониторинг

**Роль в системе:**
Grafana, Loki и Prometheus используются для мониторинга системы, сбора метрик и логирования запросов, что позволяет анализировать поведение системы в реальном времени.

**Конфигурация:**

* **Grafana:** Визуализация метрик
* **Loki:** Логирование
* **Prometheus:** Сбор метрик

**Статус:** Конфигурация мониторинга и логирования подлежит доработке с добавлением дополнительных метрик и алертов.

---
