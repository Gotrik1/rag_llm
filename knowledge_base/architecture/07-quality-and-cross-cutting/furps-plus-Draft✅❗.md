# FURPS+ — Требования к качеству

## Назначение

Систематизированные нефункциональные требования по модели FURPS+.
Конкретные, измеримые, без абстрактных "быстро и надёжно".

---

## F — Functionality (Функциональность)

| Требование                                                  | Метрика                      | Приоритет |
| ----------------------------------------------------------- | ---------------------------- | --------- |
| Мультитенантность: данные одного тенанта недоступны другому | 100% изоляция, 0 утечек      | P0        |
| RBAC: 4 роли (owner, admin, manager, viewer)                | Все роли покрыты тестами     | P0        |
| Импорт данных WB/OZON: полнота загрузки                     | ≥ 99.9% строк без потерь     | P0        |
| ClickHouse: финансовые отчёты генерируются корректно        | Отклонение от PG < 0.01 руб. | P0        |

---

## U — Usability (Удобство)

| Требование                              | Метрика                         | Приоритет |
| --------------------------------------- | ------------------------------- | --------- |
| Время до первой значимой страницы (FCP) | < 1.5 сек на LTE                | P1        |
| Время загрузки финансового отчёта       | < 3 сек (1000 строк)            | P1        |
| Ошибки формы: понятные сообщения        | 100% ошибок с текстом, не кодом | P1        |
| Работа на мобильных устройствах         | Responsive, 320px+              | P2        |

---

## R — Reliability (Надёжность)

| Требование                                        | Метрика                              | Приоритет |
| ------------------------------------------------- | ------------------------------------ | --------- |
| Uptime production                                 | ≥ 99.5% в месяц (< 3.6 ч даунтайма)  | P0        |
| RTO (Recovery Time Objective)                     | < 30 минут                           | P0        |
| RPO (Recovery Point Objective)                    | < 1 час                              | P0        |
| Graceful degradation при недоступности ClickHouse | Базовый функционал через PG работает | P1        |
| Retry на внешние API (WB, OZON)                   | 3 попытки с экспоненциальным backoff | P1        |

---

## P — Performance (Производительность)

| Требование                     | Метрика                 | Приоритет |
| ------------------------------ | ----------------------- | --------- |
| API response time (p95)        | < 500 мс при 100 RPS    | P0        |
| API response time (p99)        | < 2 сек                 | P1        |
| ClickHouse: агрегация за месяц | < 5 сек (10M строк)     | P1        |
| Одновременные пользователи     | ≥ 50 без деградации     | P1        |
| PostgreSQL: max_connections    | ≤ 100 (через PgBouncer) | P1        |

---

## S — Supportability (Поддерживаемость)

| Требование                     | Метрика                                           | Приоритет |
| ------------------------------ | ------------------------------------------------- | --------- |
| Структурированные логи (JSON)  | 100% логов в production                           | P0        |
| Health endpoints               | `/health/live`, `/health/ready` на каждом сервисе | P0        |
| Метрики в Grafana              | CPU, RAM, RPS, p95 latency                        | P1        |
| Документация API (Swagger)     | Покрытие 100% публичных эндпоинтов                | P1        |
| Откат деплоя                   | За < 5 минут через CI/CD                          | P1        |
| Runbook для типовых инцидентов | Restart, reset, healthcheck                       | P2        |

---

## + — Constraints (Ограничения)

| Тип                | Ограничение                                                        |
| ------------------ | ------------------------------------------------------------------ |
| **Design**         | Монолитный backend (Node.js), Next.js frontend — без микросервисов |
| **Implementation** | TypeScript обязателен везде                                        |
| **Interface**      | REST API + Swagger документация                                    |
| **Physical**       | 2 сервера на стенд (app + db), VPS в РФ                            |
| **Legal**          | Данные WB/OZON — коммерческая тайна, не выносить за периметр       |
