# Security Architecture & Threat Model

## Назначение

Описывает архитектуру безопасности системы и модель угроз (Threat Model) по методологии STRIDE.
"Безопасность без иллюзий" — честная оценка текущего состояния и приоритетных мер.

---

## Контекст безопасности

### Что защищаем

| Актив                                       | Критичность | Описание                      |
| ------------------------------------------- | ----------- | ----------------------------- |
| Финансовые данные тенантов (WB/OZON отчёты) | Критическая | Коммерческая тайна            |
| JWT токены пользователей                    | Высокая     | Доступ к системе              |
| API ключи WB/OZON                           | Высокая     | Доступ к данным маркетплейсов |
| Учётные данные БД                           | Критическая | Полный доступ к данным        |
| Секреты инфраструктуры (Ansible Vault)      | Высокая     | Доступ к серверам             |

## STRIDE Threat Model

### S — Spoofing (Подмена идентичности)

| Угроза                                               | Вектор           | Митигация                                      | Статус      |
| ---------------------------------------------------- | ---------------- | ---------------------------------------------- | ----------- |
| Перехват JWT и использование от другого пользователя | Stolen token     | Короткий TTL (15 мин access), refresh rotation | Реализовано |
| Подмена tenant_id в запросе                          | Параметр запроса | Tenant ID из JWT, не из параметра              | Реализовано |
| Brute-force пароля                                   | Login endpoint   | Rate limiting (10 попыток/мин)                 | В плане     |

### T — Tampering (Подделка данных)

| Угроза                               | Вектор                    | Митигация                                    | Статус      |
| ------------------------------------ | ------------------------- | -------------------------------------------- | ----------- |
| SQL инъекция                         | Query параметры           | Parameterized queries, ORM                   | Реализовано |
| Модификация JWT payload              | Изменение claims          | RS256 подпись, верификация на каждом запросе | Реализовано |
| Подделка финансовых данных через API | PUT/PATCH без авторизации | RBAC проверки на всех мутациях               | Частично    |

### R — Repudiation (Отказ от авторства)

| Угроза                                     | Митигация                                          | Статус  |
| ------------------------------------------ | -------------------------------------------------- | ------- |
| Отсутствие аудит-лога критических действий | Audit log для: логин, смена прав, изменение данных | В плане |

### I — Information Disclosure (Раскрытие информации)

| Угроза                        | Вектор                       | Митигация                                       | Статус      |
| ----------------------------- | ---------------------------- | ----------------------------------------------- | ----------- |
| Межтенантная утечка данных    | Запрос без tenant_id фильтра | Row-level security + фильтр в каждом запросе    | Реализовано |
| Детальные ошибки в production | Stack trace в 500 ответах    | Обобщённые ошибки в prod, детали только в логах | Частично    |
| Credentials в коде / git      | Хардкод паролей              | Ansible Vault + ENV vars, git-secrets scan      | В плане     |

### D — Denial of Service (Отказ в обслуживании)

| Угроза                                     | Митигация                                    | Статус   |
| ------------------------------------------ | -------------------------------------------- | -------- |
| Flood API запросами                        | Rate limiting на Nginx/API уровне            | В плане  |
| Медленные запросы к CH (тяжёлые агрегации) | Query timeout (30 сек), readonly user для CH | Частично |
| Переполнение диска логами                  | Log rotation, алерт при > 80% disk           | В плане  |

### E — Elevation of Privilege (Повышение привилегий)

| Угроза                                    | Вектор                             | Митигация                             | Статус   |
| ----------------------------------------- | ---------------------------------- | ------------------------------------- | -------- |
| Горизонтальное повышение (viewer → admin) | RBAC bypass                        | RBAC проверки через middleware, тесты | Частично |
| Вертикальное повышение (admin → system)   | Нет разделения system/tenant admin | Разделение ролей в роадмапе           | В плане  |

## Текущая архитектура безопасности

```markdown
[Client]
   │ HTTPS (TLS 1.3)
   ▼
[Nginx] — rate limiting, SSL termination
   │
   ▼
[Backend API]
   ├── JWT verification (RS256)
   ├── RBAC middleware
   ├── Tenant isolation middleware
   └── Input validation (zod/joi)
   │
   ├──► [PostgreSQL] — parameterized queries, отдельный user для app
   └──► [ClickHouse] — readonly user для SELECT, отдельный для INSERT
```
