# ADR-0003. Атомарная единица данных юнит-экономики

**Статус:** Approved
**Дата:** 2026-01-16
**Автор:** [Имя/Команда]

## Контекст

На момент принятия решения основным пользовательским измерением является SKU. Ввод и чтение данных осуществляется через Google Sheets. Ввод данных на уровне barcode добавляется в рамках MVP Web \+ BFF. В переходный период (\~6 месяцев) системы ввода SKU-only и SKU+barcode существуют параллельно.

## Решение

В качестве **атомарной единицы данных юнит-экономики** зафиксирована тройка:

**date \+ SKU (+баркод ?)**

Каждый расчёт и каждое пользовательское значение должны быть привязаны к данной атомарной единице.

В переходный период допускается ввод данных на уровне date \+ SKU без явного указания barcode. В этом случае система интерпретирует такие данные как применимые ко всем баркодам SKU с последующей нормализацией до атомарной модели.

## Обоснование

* Баркод является минимальной технической единицей учёта маркетплейса

* SKU является основной бизнес-единицей аналитики

* Дата необходима для корректного временного анализа

* Модель поддерживает поэтапный переход от SKU-first ввода к barcode-level без изменения ядра расчётов

## Альтернативы

* **SKU без баркода** — отклонено из\-за потери технической точности

* **Только баркод** — отклонено из\-за потери бизнес-логики

## Последствия

* Повышение прозрачности расчётов

* Увеличение объёма данных (осознанный компромисс)

* В переходный период возрастает сложность интерпретации источника данных

* Требуется явное документирование правил нормализации
